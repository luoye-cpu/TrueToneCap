## 3. 方法

**格子定义**：一格 = 一次用户动作（真实键位 + 真实拖拽，不注入编码参数）+ 一个外部裁判读数 + 产品自述的一行日志。三方不一致才叫发现，一致才叫过。

**分级沿用 T1/T2/T3**（09-27 §3.2），本轮新增一条硬规矩：**凡是"未判"的格子，必须写明卡在第几手**（起手没窗 / 拖拽没选中 / 没有完成行 / 裁判读不出 / 声明与像素不同向），否则下一轮没法接着推。

**驱动**：产品进程 + UIA（`MainWindowHandle` 对 WinUI3 恒 0 ⇒ 按 PID 枚举、取子树元素数最大的宿主窗）+ `PostMessage` 拖拽（不动用户光标）。格式切换走界面下拉的 `SelectionItemPattern.Select()`，一次起进程能跑完 6 个格式——这比"每格重启一次"便宜一个量级，也更接近真实用法（改设置不重启）。

## 5. 实机纪律（每一条都是这轮欠的债，不是倡议）

1. **独占**：跑格子期间不并行动 `bin/`、设置文件、剪贴板——这三样是测试与产品共享的，动一次就改了用户机器。门禁轮与实机轮**永不重叠**。
2. **设置**：按字节临时改，收尾原样还原并**复算 sha256 与轮前相同**（现值 `A945F48F…` 那把尺）。W2① 是例外：那一格就是要用原样配置跑，不许偷偷改。
3. **剪贴板**：轮前拍快照（文本 + 位图），轮末还原；还原不了就如实记，不假装成功。
4. **进程**：只杀本次起的 PID，收尾 Esc 关窗；起手前确认"本进程只有一个 `TTC_HC` 全屏窗"，否则读数会归错轮。
5. **产物**：一律落 `tests/output/realmachine-2026-10-01/`，不写用户目录；样张留裁判读不出的那几份，其余按格删，别把仓库灌满。
6. **判据不依赖焦点**：`PrintWindow(hwnd,…,2)` 抓被遮挡窗；**第一帧可能是未合成的平帧** ⇒ 取内容读数用第二帧（§09-30 已付过学费）。
7. **等自述行，不固定睡**：副作用类读数（剪贴板、落盘）必须等产品自己写出完成行再取。
8. **目视在先**：临时钩子（`TTC_FORCE_*`）拆掉之前完成需要眼睛的那几格。
9. **不 commit / 不 push / 不打 tag**：逐次授权，且授权前本机验证要跑完。
10. 会话不锁屏、不休眠（WGC 在会话离开时拿不到帧，会把超时误判成产品缺陷）。
