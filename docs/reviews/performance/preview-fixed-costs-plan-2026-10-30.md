## 判词

1. **顺序：仪表 → 启动预烘图集 → 启动 1.07s → SDR 共享槽 → 设备复用。** 前两项便宜、收益有读数；
   第三项没有数据就是空想；第四项（SDR 槽）的收益**还没量过**，本计划把它拆成"先量、够大再做"；
   设备复用风险最高，放最后。
2. **SDR 有两条完全不同的含义，必须分开对待**：① **SDR 显示器**（没有 Float16 会话，预览只能吃 8-bit）；
   ② **SDR 输出**（HDR 屏上用户关掉 HDR 输出，但 Float16 会话仍然存在）。
   本计划对 ① **一字不改**（今天怎么走就怎么走），对 ② 走与 HDR 屏相同的槽路径。唯一例外是阶段 3 的
   "SDR 屏预览直接采样 8-bit 槽"——本机没有 SDR 屏，**列为不做**（理由见 §7）。
3. **每一阶段都必须能单独回退**，且回退动作只有一种形态：环境开关或删除单个提交，不需要数据迁移。

## 2. 阶段 1：启动时预烘工具条图集

**目标**：第一扇预览窗的"等预热 19–35ms"变 0（第 2 扇起已是 3ms）。

**做法**
1. 把 `BuildAtlasLayout` 的 CPU 腿抽成**静态核心** `BuildAtlasLayoutCore(AtlasInputs)`，
   实例版只负责"从实例字段凑 `AtlasInputs`"再调核心；`AtlasInputs` 就是 `BuildAtlasCacheKey` 的输入集
   （DPI、字体/字号、下拉状态、悬停标题、工具条四条文案、马赛克两标签、前 64 条下拉项、可见文字层签名）。
2. 启动投递点选在**主窗口构造末尾、DPI 已知之后**（`MainWindow` 已拿到主屏 `uiScale`），
   用"默认档"输入（无下拉、无悬停、无文字层）后台跑一次，产物写进现有跨窗缓存。
3. 开窗侧**不改**：`AtlasCacheHot()` 命中就用，未命中照旧投递预热或现烘。

**为什么不用"启动时装一张假窗"**：构造里建 D3D11 设备要 33–57ms，比要省的那 20–35ms 还贵。

**SDR 维度**：与 HDR/SDR 无关（图集只依赖 DPI/字体/文案）。⚠ 但 DPI 必须取**主屏**，不能写死 1.5。

**判据（全部要有牙）**
- 启动投递用的输入集 == 开窗默认态的输入集（同一函数构造键；测试里两处各建一次键并断言相等）。
- 投递点在"DPI 发布之后"、且不在 UI 线程上跑排版（与现有预热同一条纪律）。
- 缓存命中时首窗关键路径排版仍记 0（现有判据复用）。
- 变异：把投递挪到 DPI 发布之前 ⇒ 首窗必 miss（读真机日志红）；把输入集少放一项 ⇒ 键不等那条红。

**门禁**：共同门禁 + 两次冷启动真机读数（首窗 `预热排版` 应为 0、`等` 应为 0）。
**回退**：删掉启动那一次投递（保留静态核心，实例版仍在用）。

## 3. 阶段 2：启动 1.07s（按 0.1 的拆分决定动哪块）

**约束（先写死，防止顺手把旧缺陷请回来）**
- `_uiReady` 守卫不许动：设置回显时触发的 `SelectionChanged` 一律不落盘（2026-10-29 已修过同类）。
- 设置写盘仍是**差集写盘**：默认值键不落盘（2026-09-24 之后的口径）。
- 任何"延后"只能延后**视觉回显**，不能延后**读取**：格式/质量/输出路径必须在那次截图发生之前已生效。

**候选动作（按 0.1 结果取用，每次只做一个）**
- (a) 控件回显（下拉填充、滑块位置、开关状态）挪到首帧呈现之后一个低优先级消息里；
- (b) 本地化/托盘/OCR 语言注册挪到后台（若 0.1 证明它们在构造的关键路径上）；
- (c) XAML：把非首屏页（OCR 设置、关于页）改成惰性加载。

**判据**
- 启动日志：`启动: 进程到主窗口` 下降，`XAML 初始化` / `设置加载与回显` 的下降量与搬走的段对得上（守恒）。
- 功能：冷启动后 500ms 内设置页显示的是**磁盘上的值**而不是默认值（截图或探针读控件状态）；
  紧接着改一项设置 → 关掉再开 → 值仍在（证明没被 `_uiReady` 守卫或差集写盘吃掉）。
- 变异：把回显挪到首帧之前但不加守卫 ⇒ "设置页显示默认值"那条必须红（模拟一次）。

**SDR 维度**：无（启动路径与显示色彩无关）。
**回退**：逐个提交回退；每个动作独立开关更好（`TTC_DEFER_SETTINGS_ECHO=0`）。

## 4. 阶段 3：SDR 共享槽（#31 / #32 的合并收口）

> **先进门条件**：0.2 的读数必须证明"捕获内 SDR 那段 ≥ 5ms（warm）"或"预览前 2s 的后台回读真的在抢 GPU 锁"。
> 两条都不成立 ⇒ **判死，不做**（省下来的是个位数毫秒，不值得多一块槽与一套失败退路）。

### 4.1 设计
1. **槽下沉到会话**：`PooledSession` 现在只给 Float16 建槽。改成"每会话一块槽"，
   格式取该会话自己的纹理格式（HDR 会话 = `R16G16B16A16_Float`，SDR 会话 = `B8G8R8A8_UNorm`），
   纪律一字不改：`Shared | SharedNTHandle` 建纹理、`IDXGIResource1::CreateSharedHandle` 取句柄、
   消费侧 `OpenSharedResource1`、被取走期间不更新、上一任未交还就换新。
   **降风险的一个事实**：建槽本身已经是格式参数化的（`CreateSharedTextureLocked(w, h, format)`，
   调用处传的是 `_latestTexture.Description.Format`），HDR 专属的只有 `TryFreezeShared` 里那条
   `!= R16G16B16A16_Float` 的格式闸 —— 把它改成"等于本会话格式"，槽就能为 8-bit 会话复用。
   像素读取侧也已有 `byte[]` 的重载（staging 格式同样是参数化的），不需要新写搬运算术。
2. **同一次捕获里冻两块**：`CaptureMonitorInternal` 在"取槽紧跟取像素"那一段同时冻 HDR 槽与 SDR 槽，
   两块各自带 `(handle, w, h, release)`，作为**一个所有权对**交出（只释放一半 = 槽永久冻结）。
3. **扩展范围屏（HDR 或广色域 SDR）上不再整帧回读 SDR**：`CaptureResult.SdrPixels = null`；
   选区确定后按矩形回读 `ReadSharedRegionSdr(handle, x, y, w, h)` 得 `sdrRegion`。
4. **纯 SDR 屏（无 Float16）走今天的路，一字不改**：不建 SDR 槽、照常整帧取、照常 CPU 上传预览。
   → 这就是"SDR 下也能正常运行"的保证：那条分支连新 API 都不会被调到（判据钉住）。
5. **多屏拼接**：槽是单屏纹理，拼接路径整帧取，今天怎么走就怎么走（与 HDR 槽同一条限制）。
6. **诊断开关必须能强制退路**：
   - `TTC_SDR_SHARED=0` → 不冻 SDR 槽、照常整帧取（A/B 用）；
   - `TTC_PREVIEW_SHARED=0` → 两块槽都不冻（A/B 用）；
   - `TTC_FORCE_SDR=1` → **强制整帧取 SDR**（它要把 SDR 帧喂预览，不能是 null），并交还两块槽；
   - `TTC_NO_FLOAT16=1`（新增，诊断）→ 强制"没有扩展范围会话"，用来在本机（HDR 屏）上把 ① 那条
     SDR-only 代码路径真跑一遍（见 §7）。落点：`WgcCaptureService.CanDeliverExtendedRange` 里加一处
     环境开关短路（返回 false），下游 `GetOrCreateHdrSession`/捕获分支自然走 SDR 那条，不需要第二处改动。
7. **语义不变式（必须写进注释，不许只在文档里）**：
   - 预览画的 HDR 帧 == 保存的 HDR 像素（B-3 已由构造保证，不得退化）；
   - **SDR 区域 == 本次捕获本会拿到的那一帧 SDR 的同一块**（两块槽来自两个独立会话，
     SDR 与 HDR 相差一帧是既有事实，不做新承诺，但要写清楚）；
   - SDR 槽被拒绝（句柄轮换/越界）⇒ 显式 Warn + 退回"整帧取一次 SDR"（不是退回 SDR-only 预览）。

### 4.2 判据（每条都要有变异）
- 冻 SDR 槽与冻 HDR 槽在同一段、同一次捕获里；两块槽的 `held` 成对置真、成对交还（半交还即红）。
- 槽格式必须是会话自己的格式（SDR 槽必须是 `B8G8R8A8_UNorm`，HDR 槽必须是 `R16G16B16A16_Float`）。
- 区域回读必须 `CopySubresourceRegion` 且只读矩形；越界与句柄不符各自拒绝并 Warn。
- 扩展范围屏上"不整帧回读 SDR"必须与"槽已冻"同一条件（少一个 ⇒ 既没像素也没槽，预览直接黑）。
- 纯 SDR 屏分支里**零调用**新 API（源码锁 + 一处"关掉 HDR 会话"的运行时臂）。
- `TTC_FORCE_SDR=1` 必须强制整帧取 SDR（否则那条诊断开关会变成"预览无帧"）。
- 交还在 `finally` 兜底：Cancel / 保存 / 初始化失败 / 异常四条路都不漏。

### 4.3 探针
- `--frame-handoff-probe` 增加三臂：
  - ⑧ **SDR 槽 == 同一帧 SDR 纹理**：冻槽后从**同一块冻结纹理**整幅读回，逐字节比 3840×2160×4，
    必须 0 处不同；
  - ⑨ 运动画面下连跑 6 次，6/6 相等（防"静态桌面碰巧一样"）；
  - ⑩ 失败退路：故意用错句柄调用 ⇒ 必须拒绝且 Warn，上层能退回整帧取。
- `--preview-ui-probe` 14 相全绿（HDR 路径不变），另加一相"`TTC_SDR_SHARED=0` 下同样全绿"
  （即上面 4.1-6 的 A/B）。

### 4.4 真机 E2E
1. 热键 → 框 1500×900 → Enter 保存；日志必须出现 `选区回读 HDR` 与 `选区回读 SDR` 两条及其毫秒；
   产物能打开、像素正常（Y 走向、色偏目测 + 与上一版同机同素材的统计量比）。
2. 同上但**带标注**保存（走 `sdrRegion`）：马赛克/箭头位置正确（这是产物里唯一真吃 SDR 像素的动作）。
3. 复制到剪贴板 / OCR / 翻译 / 贴图各一次（都吃 `sdrRegion`）。
4. `TTC_SDR_SHARED=0` 与 `TTC_PREVIEW_SHARED=0` 各跑一遍同样的三条，产物与 1–3 表现一致。
5. `TTC_FORCE_SDR=1`：预览来自 SDR、能框选、能保存。
6. `TTC_NO_FLOAT16=1`：**纯 SDR 屏模拟**（本机 HDR 屏上强制无扩展范围会话）——预览来自 SDR 帧、
   框选、保存 SDR PNG、带标注保存；这条是本机能做到的、对 ① 的最强证据。

### 4.5 回退
`TTC_SDR_SHARED=0` 即回到今天；若问题是结构性的（槽纪律本身），删掉"冻 SDR 槽"那一处调用，
SDR 自动回整帧取（设计上就是这个形状）。

## 5. 阶段 4：预览窗复用一块 D3D11 设备

**目标**：每扇窗省 `窗口构造 33–57ms`。

**做法**：`HdrCaptureWindow` 构造里那次 `D3D11CreateDevice` 换成借用一块**进程级惰性设备**
（或捕获服务那块匹配适配器的设备），窗口只建自己的交换链与纹理。

**代价（必须写进计划，不许低估）**
- D3D11 一个设备只有一个 `ImmediateContext` ⇒ 每窗的 `_gpuLock` 必须换成**同一把全局锁**，
  否则跨线程上下文争用（这是本仓最容易出"复现不出来的花屏"的那一族）。
- 设备丢失从"每窗各自重建"变成"两个消费者一起重建"：重建路径（`GetDeviceRemovedReason` 那一套）
  要重写成"共享设备的复活广播"。
- 共享槽的消费侧 `OpenSharedResource1` 在共享设备上做，槽创建在捕获侧设备上做——跨设备那条已经验证过，
  但"同一设备开自己共享的纹理"是**另一条没验证过的组合**，要单独测。

**判据**
- 连续开 20 扇窗（探针循环）零设备丢失、零黑帧；
- 设备丢失故障注入（人为 `DXGI_ERROR_DEVICE_REMOVED`）后两窗都能重建；
- 全局锁：探针里两窗交替渲染 200 帧，无 `Map` 超时、无数据竞争迹象（现有 500ms 超时日志为 0）。

**SDR 维度**：无差别（设备与色彩无关），但要在 `TTC_NO_FLOAT16=1` 下重跑一次。
**回退**：`TTC_PREVIEW_SHARED_DEVICE=0` 回到每窗建设备。

## 6. SDR 矩阵（每阶段都要过一遍这张表）

| 环境 | 阶段 1（图集） | 阶段 2（启动） | 阶段 3（SDR 槽） | 阶段 4（设备） |
|---|---|---|---|---|
| HDR 屏 + HDR 输出开 | 同 HDR | 同 HDR | 走槽；SDR 区域后读 | 同 HDR |
| HDR 屏 + HDR 输出关（②） | 无关 | 无关 | **同 HDR**（Float16 会话仍存在） | 同 HDR |
| 广色域 SDR 屏（有 Float16） | 无关 | 无关 | **同 HDR**（这一档本机没有，靠 `CanDeliverExtendedRange` 分支的判据） | 同 HDR |
| 纯 SDR 屏（①，无 Float16） | 无关 | 无关 | **一字不改**；`TTC_NO_FLOAT16=1` 模拟验证 | 同 HDR |
| `TTC_FORCE_SDR=1` | 无关 | 无关 | 强制整帧取 SDR + 交还两槽 | 无关 |

**本机限制（必须如实写进报告）**：本机只有一块 HDR 屏（SAC2765）。①（纯 SDR 屏）与
"广色域 SDR 屏"两档只能靠 `TTC_NO_FLOAT16=1` 强制分支 + 结构锁，**不是真机验证**。
要真机验证需接一块 SDR 屏（#46 的一部分），或把系统 HDR 关掉做一次"②"的近似（那仍是 HDR 面板、
仍是 Float16 会话，只是输出档变了——**不能**当 ① 的证据）。

  扩到 `B8G8R8A8_UNorm`（参考白/alpha 那一刀要在 GPU 侧重做），且收益只落在 ① 这一档——
  **本机没有 SDR 屏**，做出来也无法真机验收。等有第二块屏（#46）再谈。
- **路线 A（8-bit 产物也从 HDR 帧出）**：改写 2026-09-22 拍板的源精度口径，只有维护者能定；
  且 warm 捕获只剩 28–33ms，收益上限被压死。
- **#45 图集生在 GPU 里**：跨窗缓存落地后它只能省首窗 20–35ms（阶段 1 更便宜地拿到同一笔）。
- **#46 跨屏/不同 DPI**：待硬件。

## 8. 体量与建议

| 阶段 | 体量 | 主要驱动 |
|---|---|---|
| 0 仪表 | 小 | 三处打点 + 两条结构锁 |
| 1 启动预烘图集 | 小–中 | `BuildAtlasLayout` 抽静态核心（约 200 行方法要拆干净） |
| 2 启动 1.07s | 中（未定） | 取决于 0.1 拆出来的形状 |
| 3 SDR 共享槽 | 大 | 槽下沉到会话、两块槽的所有权对、四条诊断开关、探针三臂 |
| 4 设备复用 | 大 | 全局锁 + 设备丢失广播 + 20 窗回归 |

**建议**：先做 0 + 1（同一批，能一并验证落盘），再做 2 的拆解部分；3 与 4 各自单独一批，
且 3 必须等 0.2 的读数。
