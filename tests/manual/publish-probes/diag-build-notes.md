# 诊断包说明 / Diagnostic build notes

**这个包不是新版本。** 产品版本仍是 `0.3.4-beta`，二进制版本 `0.3.4.0`，与正式发布的
`TrueToneCap-v0.3.4-beta-win-x64.7z` 同源，只多了**一处日志改动**。目录名后缀 `-diag1`
只为和正式包区分，不代表 0.3.5。

## 改了什么

分支 `diag/wgc-item-hr-info`，基于 tag `v0.3.4-beta`，仅动
`src/TrueToneCap.App/Services/WgcCaptureService.cs`：

- 把"捕获会话建不起来"这条路径上 8 处日志从 Debug 提到 Info；
- 补 1 处：`方法2(vtable)` 静默失败时现在也打印它最后的 HRESULT。

**没有改动任何控制流、捕获逻辑、色彩/编码链。** 提级的全是本来就在写的行，只是让它落进日志文件。

## 为什么发给你

你报的这句

```
WGC 捕获失败: 无法为显示器 0xXXXXX 创建 WGC 会话
```

在 0.3.3 / 0.3.4 里只是一个包装层。真正的原因（是哪一步、什么 HRESULT）本来有记录，但
记录在 Debug 级——而 Debug 级在**任何情况下都不会写进日志文件**。所以你那份日志里看不到根因，
我们也只能看到这句包装。装上这个包之后，同样的操作就会把根因写进日志。

## 请你做的三步

1. 解压到一个**新文件夹**（不要覆盖现有安装），运行 `TrueToneCap.exe`。
   设置与截图记录不会被动到；这个包和正式版可以并存。
2. 按平时的方式**复现一次失败**（按一下截图热键，看到红色报错即可），然后**再按一次**——
   多一次是为了排除偶发。
3. 打开应用目录下的 `log\` 文件夹，把**当天那个 `app_*.log` 整个文件**发回来
   （不用截取、不用筛选，整份发）。

> 不需要你去设置里调任何日志开关——这个包的根因信息默认就会写。

## 附带信息（能填就填，不填也能开工）

- 这台机器是不是：**远程桌面 / 虚拟机 / 采集卡或虚拟显示器 / 远程协助中**？（其中任意一个都直接改变结论）

- 显卡型号，以及是否装了官方驱动（不是" Microsoft 基本显示驱动"）
- 平时用的截图工具（Snip 截图 / ShareX / PrintScreen）在这台机器上正常吗？
